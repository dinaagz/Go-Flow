## Problèmes Prioritaires

**[P1] `dv-search` (recherche du devis) oubliée du passage au debounce** — `dvFilterChange()` s'exécute encore de façon synchrone à chaque frappe (écriture localStorage + reconstruction complète du panier devis). Le devis est l'écran à plus fort enjeu (PDF client), donc l'endroit où cette incohérence de réactivité se voit le plus. *Fix* : `const dvFilterChangeDeb=debounce(dvFilterChange);` et basculer l'`oninput`. → `/impeccable optimize`

**[P2] Les raccourcis `/`, `n`, `?` ignorent les dropdowns non-modaux ouverts** — Échap les ferme correctement, mais ces trois raccourcis ne vérifient que `.overlay.open`. Ouvrir "Plus ▾" puis appuyer sur `n` empile une modale par-dessus un dropdown resté ouvert, sans interaction de clic pour le refermer. *Fix* : étendre la garde pour inclure `.col-picker-drop.open,.user-menu.open,.tb-more-drop.open`, ou fermer ces dropdowns avant d'agir. → `/impeccable harden`

**[P2] Les barres de progression n'exposent toujours aucune valeur accessible** — aucun `role="progressbar"`/`aria-valuenow` malgré le pourcentage déjà calculé et centralisé dans `setProgress()`. Un import en masse (potentiellement des centaines de lignes) ne donne aucun retour de progression à un utilisateur de lecteur d'écran. *Fix* : ajouter les attributs ARIA, les mettre à jour dans `setProgress()`. → `/impeccable harden`

**[P3] La conversion mobile en bottom-sheet n'a pas de voile (scrim)** — contrairement aux vraies modales `.overlay` qui assombrissent toujours le fond, ces panneaux fixes plein-largeur n'ont rien pour signaler "ceci est une couche temporaire, touchez ailleurs pour fermer". *Fix* : ajouter un voile semi-transparent sous la même media query. → `/impeccable polish`
